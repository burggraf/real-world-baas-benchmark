# TrailBase adapter

Compatibility is pinned to TrailBase server `v0.33.1` (`darwin-arm64`) and the
official npm SDK `trailbase@0.14.0`. npm integrity is
`sha512-IyD+TuPpgWOf7NXIWpZpE2bJx85GAQEtmFgcdehDUveL8osNg4C2H3Ey/0PJF9ahAEPYneKsGi4rQzi7tlZj0Q==`
(SHA-1 shasum `2208db5fb72030c7d87119bdf5807affe3560342`). The release binary is
`.tools/trailbase-0.33.1/trail` (or `TRAILBASE_BIN`); its local SHA-256 is
`cf870bd8daef2a9c5ae26d34267618b29961188ef3be312722f363538ed787fb`.
The downloaded release archive SHA-256 is
`72ca231b0b02c51da587c69b120107312b1dd649bf6140db4f8101d0b58a4622`.

The local endpoint defaults to `http://127.0.0.1:8090`; `TRAILBASE_URL` may
select another loopback HTTP port. `TRAILBASE_DATA_DIR` selects the ignored
depot. An empty depot is initialized with the repository config and migration;
`reset` removes only an empty depot or one with a valid, dead lifecycle marker.
The server is always spawned without a shell and stopped by the owning process.
First-admin output is line-buffered and password-redacted.

The downloaded v0.33.1 executable has a compatibility defect: HTTP registration
writes `_user.unverified_email`, while `trail user verify` still updates a removed
legacy `verified` column. Setup therefore stops only its owned server and performs
one parameterized transaction that moves the exact expected address from
`unverified_email` to `email` for a validated UUID, without touching password,
hash, or admin fields. It requires exactly one changed row and verifies the
result before restart. Promotion and deletion still use bounded, shell-free
official CLI commands by verified email. No password is passed in argv or
written to process logs.

Canonical domain identities are strict 15-character lowercase `publicId` values.
The `profiles.authId` BLOB references TrailBase `_user(id)` separately. Tenant
relations use portable IDs and composite foreign keys; Record APIs retain an
internal integer primary key used for every read/update/delete. Ordinary Record
API rules are tenant-scoped. The promoted setup user has explicit `_user.admin`
gates for bounded seed and cleanup only; measured sessions have no admin path.
Task and comment activity rows are generated by database triggers. Canonical
seed rows carry a hidden setup-only marker so repeatable dataset activity counts
are not inflated by those triggers.
